\subsection{Spreadsheet change inference}
SheetDiff infers changes between spreadsheet versions and presents them in a
single contextual view~\cite{sheetdiff}. RowColAlign extends longest-common-subsequence reasoning
to two-dimensional alignment and evaluates edit recovery using generated pairs
with planted changes~\cite{rowcolalign}. Its known edit history provides a
methodological precedent for controlled mutations. Our evaluation additionally
requires native observations of which mutations produce visible effects under
the chosen state-preparation policy. Edit recovery and rendered-effect coverage
have different observation units.

\subsection{Spreadsheet dependencies and testing}
Spreadsheet slicing connects dependency analysis with integrated testing and
fault localization~\cite{slicing}. DeltaSieve uses supported dependencies to
select native observation regions. Fisher et al. retain spreadsheet test cases
and use change-impact analysis to support their reuse~\cite{fisher2002testreuse}.
TACO compresses formula graphs using regularity in cell references and supports
queries over the compressed representation~\cite{tang2023taco}.
DeltaSieve follows supported conditional-formatting and chart inputs to affected
presentation regions. Its coverage obligations include inherited formatting,
automatic row geometry and object bounds alongside formula dependencies.

\subsection{Workbook comparison and native evidence}
Spreadsheet Compare documents workbook comparison reports with formula and
cell-format categories, including hidden sheets~\cite{spreadsheetcompare}.
Its documented comparison categories establish formatting-aware spreadsheet
differencing. DeltaSieve evaluates native rendered effects and records the
selected capture scope. The documentation describes change reports and a
side-by-side grid, while pairwise native image validation of reported candidates
requires evidence from the tested product and configuration.

xlCompare documents command-line comparison and exported difference reports~\cite{xlcompare}.
DiffEngineX documents whole-workbook and folder comparisons, report workbooks,
and comparisons of formulas and constants. Its help explicitly excludes chart
comparison~\cite{diffenginex}. xlCompare also documents configurable formatting comparisons~\cite{xlcompareHelp}.
These capabilities support the shared-input pilot with exported reports. A report of edited cell inputs and an
observation of their dependent rendered consequences answer different questions.
The pilot must therefore record the tested options and report coverage instead
of treating every comparator as an interchangeable visual oracle.

Synkronizer's edition documentation lists content, formatting and Excel-name
comparison features~\cite{synkronizer}. SpreadsheetsDiff advertises two- and
three-way comparison, key-column matching, and workbook/VBA comparison
features~\cite{spreadsheetsdiff}. A native pixel-observation contract and its tested
coverage require separate verification for each product and version.

\subsection{Cross-system testing and parsing}
SQuaLity examines barriers to reusing database test suites across systems,
including configuration and execution dependencies~\cite{squality}. This suggests
recording the renderer and environment when reusing observations. The analogy
does not transfer database test adequacy guarantees to spreadsheet rendering.
SheetReader's specialized parsing work~\cite{sheetreader} is relevant to efficient
package inspection, whose cost must be separated from native rendering cost.

\subsection{Selective regression testing and visual models}
Ekstazi selects regression tests through recorded file dependencies~\cite{ekstazi}.
It tracks dynamically used files and their checksums.
Its separation of analysis, execution and dependency collection motivates
measuring selection overhead together with avoided work. DeltaSieve's
spreadsheet dependency model and native image observations require their own
coverage evaluation.

ReDeCheck detects potential responsive web layout failures from structural
models~\cite{redecheck}. VISER renders reported issues in a browser and manipulates
element opacity to determine whether an effect is visible~\cite{althomali2019viser}.
VERVE extends this approach to all five ReDeCheck failure classes and uses
histogram-based image comparison~\cite{althomali2021verve}. Structural filtering
followed by targeted visual verification is therefore an established method.
DeltaSieve applies this principle to paired workbook states and spreadsheet
presentation dependencies, including effective formatting, conditional rules,
chart sources and native geometry. Its coverage evaluation must independently
assess which affected regions the selector retains.

\subsection{Visual document regression and benchmark scope}
Huang's account of the Antenna House Regression Testing System (AHRTS) describes
rasterizing baseline and new PDFs and comparing their page images pixel by
pixel~\cite{huang2014ahrts}. Document and image checksums avoid work before
more detailed comparison. This provides a document-processing precedent for
staged visual regression testing and reuse. DeltaSieve selects regions within
workbooks using spreadsheet dependencies and retains native geometry alongside
pixel observations.

The evaluated scope concerns XLSX transformations observed in Excel. VISER and
VERVE consume web pages and DOM-based layout reports. Adapting their selectors
would require a spreadsheet-specific dependency and geometry model. Applying
AHRTS through PDF export would introduce print areas, pagination and scaling
into the observation contract. These input and observation differences motivate
methodological comparison with these systems. Direct runtime rankings would
require a common task, preparation policy and capture scope.
