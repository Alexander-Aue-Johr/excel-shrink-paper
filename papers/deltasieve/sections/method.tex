\subsection{Comparison subject and observation model}
Figure~\ref{fig:comparison-algorithm} separates package analysis, native
observation and outcome accounting. The input is an original/transformed pair,
a state-preparation policy and a renderer environment. The principal comparison
opens separate owned Excel processes and observes both partners after full
rebuilding in place. Ordinary-save and pre-rebuild controls retain the effects
of serialization and calculation. Conversion of a legacy XLS source precedes
this subject and has its own failure outcome.
\input{figures/comparison-algorithm}

Let $A$ and $B$ denote the compared states, $E$ their justified relevant visual
area and $C$ the selected observation regions. The intended selector obligation
is to include every transformation-induced visual difference inside $E$ in $C$.
Pixel equality on $C$ tests the selected observations. It does not establish
that the selector met that obligation. Independent reference captures and
visible mutations evaluate this second question. Renderer variability and
unsupported dependencies remain explicit boundaries of the model.

\subsection{State preparation and attribution controls}
Opening a workbook can repair or normalize its stored representation, saving
can remove structure, and recalculation can change cached results. The comparison
therefore names the operations that produced each observed state. Let $W_0$ be
the raw package, $W_s$ its ordinary-save control and $W_r$ the rebuilt saved
control. A native optimization comparison additionally retains $W_{cp}$ after
Check Performance and Save As, and $W_{cpr}$ after rebuilding that result.
The transformed workbook has its own corresponding controls.
Figure~\ref{fig:artifact-lineage} shows these generation recipes and the
provenance required to interpret or reuse their results.
\input{figures/artifact-lineage}

The primary observation compares independently prepared rebuilt partners.
Control differences explain which changes arose while opening, saving,
optimizing or rebuilding. Ordinary Save and Save As remain distinct generation
recipes. One cannot substitute a cheaper recipe under an existing control name
and retain its evidence meaning. Legacy format conversion and explicit repair
also produce separately identified artifacts.

Each control records its parent identity, native environment and generation
recipe. A reusable control artifact saves preparation work but supplies no new
visual verdict. A comparison still needs compatible observations of both
partners. If opening or a required operation fails, that state remains
unavailable. The workflow does not manufacture its image from another state.
This separation also permits attributing a reduced package to Excel's save
behavior without crediting that reduction to the tested cleanup operation.

\subsection{Streaming change evidence}
The package analyzer uses borrowed XML byte views with bounded hierarchy and
attribute state. It resolves shared strings, cell formats and relationships before
interpreting a coordinate change. String and formula interpretation can require
decoding, but worksheet analysis does not instantiate a general XML DOM or an
Excel object per cell. This is important on bloated inputs with many empty
formatting records.

Cell evidence is written as fixed-size records containing coordinates, a
SHA-256 fingerprint and classification flags. The current record is 40 bytes.
The record stream resides in an owned scratch file instead of a heap map of
cell objects. Sorted streams are merged by coordinate, distinguishing changed,
added and removed cells. Equal stream digests avoid repeated cell comparison.
The merge is linear in the combined record counts, excluding XML parsing,
style resolution, hashing and selected dependency work. Scratch I/O is an explicit
cost of this memory organization. Shared strings, styles, layout records,
selected changes and native images remain additional memory consumers.

Figure~\ref{fig:cell-record} gives the streaming comparison algorithm. The writer
requires unique ascending numeric coordinates, rejects nested or unclosed cells,
and hashes a cell's text incrementally. A very large cell body therefore need
not become one temporary string. Record readers require complete records. A
truncated scratch file cannot become a shorter valid sheet. This strict stream
contract permits a two-way merge without a separate sorting pass for supported
ordered worksheets.
\input{figures/cell-stream-algorithm}

The fingerprint preserves distinctions that the model has not justified merging.
Unsupported serialization can therefore produce conservative extra work rather
than a semantic-equivalence claim. Canonicalizing style-table references is a
specific supported operation, not a general normalization of arbitrary formulas,
XML extensions or renderer behavior. The same byte-processing substrate serves
content comparison, supported reference scans and rebuild-eligibility facts,
while their decision predicates remain separate.

A format index has no cross-package meaning. Style identity resolves fonts,
fills, borders, number formats and base-format inheritance, so a permutation
of format tables does not create a change at every cell. Changed shared context,
including themes or unsupported style representations, retains the conservative
path. A removed blank cell can expose an inherited row or column format even
when values are unchanged. Conversely, an absent untyped blank and an empty
untyped record can supply the same blank input to a conditional rule. The full
visual fingerprint and the rule-input fingerprint therefore have different
responsibilities.

\subsection{Dependency-aware candidate selection}
Direct value, formula, style and layout changes create candidates. Effects
propagate beyond their edited coordinates. A row-height change can move later
content, a column-width change can move content to its right, and a merged or
centered span can extend the required text context. Changed inherited row
formats are coalesced into contiguous runs, with unchanged rows splitting the
runs. This reduces candidate objects while preserving the union of requested
regions.

Conditional-format selection resolves the supported rule formula, application
area and referenced inputs. A changed precedent selects the affected application
region even when its own appearance is unchanged. Local rules, area-wide inputs
and explicitly referenced inputs require different dependency scopes. Exclusion
requires unchanged supported rules, their relevant input fingerprints and layout.
Unknown names, dynamic references, extensions or unresolved scope retain fallback
coverage. DeltaSieve does not evaluate the rule to predict Excel's final color.
The native renderer supplies that observation.

Figure~\ref{fig:conditional-input} shows an unchanged rule whose precedent changes.
Selection follows the dependency to its application region. It does not infer
that unchanged serialized cells inside that region imply unchanged pixels.
\input{figures/capture-methods/05-conditional-input}

\subsection{Invert supported rule references}
Enumerating every target cell of a whole-column conditional rule would defeat
the purpose of selective rendering. For supported A1 references, DeltaSieve
instead maps each changed source coordinate back to dependent target intervals.
A relative scalar reference at row $a$ in a rule anchored at row $h$ reads source
row $a+t-h$ when applied at target row $t$. A changed source row $x$ therefore
selects target row
\[
 t=x-a+h.
\]
An absolute reference to row $a$ selects all permitted target rows when $x=a$,
and none otherwise. Columns follow the corresponding rule. Range endpoints
can independently mix absolute and relative axes. The implementation solves the
resulting axis intervals, combines row and column intervals and intersects them
with the application and comparison extents. It includes both shared and per-area
anchor interpretations conservatively for disjoint application areas.

This inversion avoids materializing the entire worksheet grid. Its work still
depends on changed inputs, supported reference expressions and application areas.
Cross-sheet references require a unique supported source sheet. Dynamic, external
or ambiguous references retain fallback. Exhaustive small-grid regression
controls compare the inverse result with direct forward reference evaluation,
including mixed axes and reversed range endpoints. These tests verify the
supported mapping, not arbitrary Excel formula semantics.

Charts have a separate dependency closure. Equal chart XML and cached series
values are insufficient because source cells can change independently of the
cache. The exclusion gate requires unchanged chart parts, supported source
references, source values and styles, source layout and visibility, conditional
dependencies, shared package context and complete equal native placement.
Chart sources are inspected beyond the worksheet capture envelope. A source
outside the visible table cannot disappear from this dependency check. Missing
partners, ambiguous names, user-shape dependencies and unsupported references
retain chart capture. A conservative mode exports every chart.

Graphical objects require both package identity and native geometry. Relationship
mapping binds an object to its actual worksheet. Supported lines include their
stroke envelope. Zero geometric height alone cannot exclude visible ink.
Cached previews of embedded objects can render even when Excel labels their
shape kind unsupported. Unsupported objects therefore prevent a finite-bound
claim unless their own explicit qualification succeeds.

\subsection{Finite observation envelopes}
The relevant envelope includes values, formulas, supported visible formatting,
text context and qualified object extents from both compared states. Removed
content therefore remains in scope. Native-qualified drawing bounds refine the
rebuilt-state envelope. Save-control changes retain their own attribution records
without automatically enlarging that distinct rebuilt comparison.

An empty exterior row cannot move earlier content. Effective-height selection
and image selection use the same lower union boundary, while earlier empty rows
remain relevant. Native zero-width and zero-height ranges keep their geometry
and a non-rendered outcome. A transition to a visible range remains a finding.
No white image is invented for a missing or zero-area observation.

Repeated inherited backgrounds need a finite-bound argument. For supported
borderless solid fills, the analyzer retains explicit cells, row and column
transitions, contextual neighbors and supported conditional application areas.
Uniform unfilled column styles beneath a solid row background introduce no
additional horizontal fill edge. Fonts and widths alone do not create such an
edge in an empty band. Column fill transitions, inherited column borders,
unknown styles and unsupported rules remain relevant. Finite row borders retain
the full width through XFD, ending vertically at the last finite row transition
and its following context~\cite{rowborderbackground}. Supported finite filters and
conditional regions remain in the envelope with following context. Full-grid
or unresolved application areas retain the conservative path.

These conditions permit less rendering without sampling the selected union.
They are relative to the supported model. An unresolved outlying object can
still force a full-grid plan and exhaust the available rendering budget.

\subsection{All-state adaptive geometry}
Figure~\ref{fig:capture-partition} illustrates the coverage invariant and the
effect of measuring the same candidate in multiple native states.
\input{figures/capture-partition}
Candidate coalescing preserves holes and worksheet identity. Independent ranges
are measured in batches through the native adapter. Every live state contributes
to image-size qualification. A range hidden in one state can be large in its
partner, so any oversized state forces further splitting. Each child is checked
again. Large hidden spans can yield zero-area leaves rather than thousands of
identical image requests.
Figure~\ref{fig:capture-02-all-state-geometry} illustrates the all-state geometry checks.
\input{figures/capture-methods/02-all-state-geometry}

The planner respects both area and edge budgets. A conservative point-to-pixel
allowance guides partitioning, but returned image dimensions are independently
validated. A single cell exceeding the budget fails instead of being omitted.
Measured row and column geometry handles hidden or irregular spans that make
a fixed cell-count tile unreliable. Later states can repartition an area and
backfill earlier observations.

Internal boundaries retain required neighboring context for overflow, merged
text and other supported layout effects. The final interior is cropped without
resampling. A context region can change rendering even when its own pixels are
later cropped. The renderer controls therefore compare a whole region with
contextual parts and check seam consistency. Agreement of one seam is a local
control, not a monolithic oracle for the workbook.

\subsection{Native image qualification}
Native images use bounded batches of Office.js \texttt{Range.getImage()}
requests, synchronized before consumption (Figure~\ref{fig:capture-03-office-sync}).
\input{figures/capture-methods/03-office-sync}

A successful API response does not prove complete capture. The worker verifies
expected dimensions, budget compliance and crop geometry before accepting the
image. Returned PNG bytes can first be hashed to avoid uploading identical
payloads. Unequal encodings still require decoded-pixel comparison, because
PNG serialization is not visual identity. Exact canonical RGBA pixels supply
the comparison, with no registration, resampling or general color tolerance.
Image receipts bind command, region, state and slot identity, preventing reordered
or incomplete upload batches from becoming comparisons of unrelated images.

Raw geometry and origins remain attached to the observation. An exterior-size
classification can admit an unpaired right or bottom extension only when each
pixel exactly repeats the common boundary. A zero-area counterpart requires
an entirely opaque-white retained extent for the corresponding empty-extent
classification. These derived classifications retain the original observations.
They do not erase changed overlapping content or establish a global tolerance.

\subsection{Attribution after a finding}
A native difference can originate in the transformation, calculation, capture
context or the environment. DeltaSieve keeps the observation while diagnostics
examine those hypotheses. The formula tracer follows supported A1 references,
absolute axes, quoted sheet names, ranges and translated shared formulas from
changed saved values. It searches for paths to random/time or environment-dependent
functions. Cycles, unsupported expressions and bounded-search exhaustion remain
explicit. The search budget limits explanation work, not capture coverage.

A path to a volatile function establishes a dependency, not exclusive causation.
Other changed pixels in the same region can have another cause. Source cached
values also cannot stand in for values saved from the compared rebuilt states.
The report distinguishes their provenance. Repeated original/original controls
and unchanged-package controls test renderer behavior independently of the
transformation. Counterfactual restoration of a suspected removed witness tests
a narrower causal mechanism. None of these operations increases pixel tolerance
or automatically clears an unrelated finding.

\subsection{Omission and evidence reuse}
Figures~\ref{fig:communication-panels} and~\ref{fig:capture-ownership} show
image transport, retained evidence and bounded capture ownership.
\input{figures/communication}

Some observations can be omitted before native work. A direct byte comparison
can establish that the original and transformed inputs are identical. ZIP
metadata alone does not authorize that omission. A separate rebuild-eligibility
check reuses dependency facts from the package scan and a strict part/feature
allowlist. Formulas, refresh sources, unknown extensions, duplicate members and
unresolved metadata keep rebuilding enabled. Cached values or an empty capture
plan do not establish calculation independence.

Completed-result reuse requires compatible source identities, selected parts,
implementation, state-preparation policy and rendering environment. Static
report-viewer assets are excluded from the renderer recipe. Uncompressed member
digests make identity independent of ZIP order and compression. A prior
part selection must cover every newly requested component. User-selected weaker
component policies remain explicit evaluation choices, with correspondingly
bounded claims. Interrupted runs and missing image receipts cannot supply
completed evidence.
