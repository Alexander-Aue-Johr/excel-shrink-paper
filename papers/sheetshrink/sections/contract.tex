\subsection{Observable spreadsheet behavior}
A spreadsheet package contains more than the populated table that a user sees.
Individual cell records can carry formatting, protection, references, or values
that affect other cells. Conversely, the presence of a stored record does not
establish that it contributes to the intended presentation. Sheet Shrink targets
production cleanup of such packages while retaining the structures needed by its
preservation contract. Aggressive historical configurations are separate test
artifacts and are excluded from the production subject of this paper.

The relevant visual area includes cells with meaningful values or formulas,
empty cells with effective visible fills or borders, and graphical objects.
Formatting inherited from rows or columns can contribute to this area. Conditional
formatting and text extending into adjacent cells can also affect what is visible.
The union of the original and transformed relevant areas is required when checking
removed content. Layout changes in otherwise empty trailing rows or columns are
permitted by the contract. Changes that move or alter relevant content remain
subject to validation.

\subsection{Information available before native loading}
The cleanup decision uses stored values, formulas, styles, references and layout
attributes. Native effective row heights and candidate before/after images are
available only in the separate validation workflow. Stored custom heights can
be retained directly. For automatically sized rows, a font-bearing blank can
still require a representative even when its payload is empty.

An Excel-hosted alternative could measure a row, remove candidates and write the
measured height as an explicit custom height. SpreadsheetML provides a
\emph{customHeight} attribute for that policy~\cite{customheight}. The evaluated cleanup
derives its compact preservation decisions from package context.

\subsection{Removal decisions and compact preservation}
The preservation strategy retains a small representative when that representative
can preserve a required effect. Row-font sentinels and guarded promotion of an
existing style into a row format are examples. Their applicability depends on
inherited formatting, gaps, merges, protection, and the available style records.
An unresolved case retains the required source representation.

The production policy admits separately guarded hidden constant tails and retains
ordinary nonempty hidden tables, including unreferenced values. Tail admission
depends on dependency and layout checks~\cite{sheetshrinkcontract}. Absence of a
reference alone does not authorize general hidden-data removal. A future Excel-hosted
cleanup stage could
measure native layout before replacing additional sentinels or whitespace
blockers. Such a stage is outside the implementation evaluated here.

\subsection{Validation and attribution boundaries}
DeltaSieve compares selected regions of independently rebuilt original and
Sheet Shrink workbooks in the same installed Excel
environment~\cite{deltasievecompanion}. Ordinary-save and rebuild
controls retain information for attributing differences introduced by Excel.
Excel save-only controls distinguish cleanup effects from changes introduced
by serialization and recalculation.
For XLS sources, conversion precedes the XLSX cleanup subject and has its own
failure accounting. A file requiring repair or inaccessible protected content
receives an explicit unsuccessful outcome.

Targeted visual equality is an observation over the selected regions. We evaluate
the selection mechanism separately with native reference captures and mutations.
Unequal pixels are retained for investigation. Repeated rendering controls,
volatile dependencies, and capture geometry help classify their cause.
