\subsection{Larger-memory-host follow-up}
The five workbook/library combinations that reached the laptop's 4\,GiB
commit ceiling were repeated on an AMD Ryzen 7 7800X3D host with sixteen
logical processors and 102,066,212,864 OS-reported physical bytes. Each
combination has three Original and three fresh Sheet Shrink pipeline attempts
at both 4\,GiB and 24\,GiB aggregate process-tree commit limits, totaling sixty
attempts. The same frozen Sheet Shrink binary uses sixteen Rayon and sixteen
writer workers with one active workbook. The controller maintains an 8\,GiB
reserve for physical RAM and commit headroom, with a 900-second per-trial
timeout. Python 3.12.14, openpyxl 3.1.5, pandas 3.0.1, R 4.6.2, readxl 1.6.0
and writexl 2.0.1 identify the tested software lane~\cite{openmemoryfollowup}.

At 4\,GiB, all fifteen Original attempts reached the memory limit, while
all fifteen fresh-cleanup pipelines completed. At 24\,GiB, the nine Original
attempts for Migration/readxl, Finance/openpyxl and QT/RR/openpyxl completed.
Migration's two pandas endpoints reached the memory limit in all six attempts.
All fifteen fresh-cleanup pipelines completed at that limit. Table~\ref{tab:open-save-followup}
retains these censored endpoints alongside successful medians. A memory-stop
termination time receives no completed-runtime ratio.

The larger limit distinguishes memory censoring from completed processing cost
for these selected cases. Native visual comparisons, a separate cleanup
benchmark and read-only evidence analysis ran concurrently. Filesystem caches
were retained. The measured ratios are descriptive paired results under that
context. This host lane retains its own configuration and observations alongside
the earlier six-worker laptop study. Across all sixty trials, sampled physical
RAM and commit headroom remained above the declared system reserve.

After the timing series, separately regenerated controls for all three inputs
matched every uncompressed member name, length and SHA-256 of the retained
native candidate identities. These representative controls contain 138, 225
and 24 members for Migration, Finance and QT/RR. Migration's native observation
uses a documented normalized baseline, and QT/RR's retained selected plan has
zero captures. The full per-trial member inventories were not retained for the
timed fresh outputs, whose archive hashes remain in the receipts. These
qualifications delimit the native/resource association. A second cleanup was
measured after each completed fresh pipeline, outside the timed endpoint.
Its recorded ZIP identity flags do not establish general cleanup idempotence.

\subsection{Enron selected-case follow-up}
\label{sec:enron-open-save-followup}
The fourth case uses the Enron workbook whose original SHA-256 begins
\texttt{7298df9a6a76}. Its original archive contains 42,710,945 compressed
bytes and 353,151,842 uncompressed member bytes. On the same larger-memory
host, six variants each received three openpyxl 3.1.5 round-trip attempts,
with a 4\,GiB process-tree commit limit, an 8\,GiB physical-RAM and commit
reserve and a 300-second timeout~\cite{enronopenmemory}.
All eighteen attempts have terminal receipts. Original and XLStylesTool
reached the memory limit in all three attempts. Fresh Sheet Shrink cleanup
followed by the library round trip completed with a median process-creation-to-exit
time of 3.021 seconds and a maximum job-commit peak of 891.4\,MiB.
Prepared Check Performance, Inquire and NXPowerLite outputs completed their
library round trips with respective medians of 1.036, 1.054 and 1.101 seconds,
and maximum job-commit peaks of approximately 535.6\,MiB.

The external prepared-output endpoints omit their tools' preparation cost.
The Sheet Shrink endpoint includes fresh cleanup, so these observations do
not establish an end-to-end speed ranking among cleaners. Memory-limited
attempts remain censored. Recorded commit peaks slightly exceed the configured
4\,GiB boundary and are retained without clamping. Concurrent native
comparisons and retained filesystem caches qualify this selected-case result.
After the timed series, a separate fresh Sheet Shrink control matched all
eighteen uncompressed member names, lengths and hashes of the retained native
candidate. Its output has 384,724 compressed bytes and 2,581,673 uncompressed
member bytes. This representative identity check links the control to the
visual audit, while preserving that audit's selected-coverage limitations.
The timed trials retain archive hashes, without full per-trial member inventories.
